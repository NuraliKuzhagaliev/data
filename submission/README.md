# Как проверить CQA Evidence

Команда **THE BOYS**. [Демо](https://cqa-evidence-the-boys.onrender.com) · [Исходники](https://github.com/NuraliKuzhagaliev/data) · [DEV results.json](../results/dev/results.json).

Код доступа передаётся в заявке. Регистрация не нужна. Первый вход после простоя бесплатного хостинга может занять около минуты. Каждый вход создаёт отдельное временное рабочее пространство. Приватный DEV и база ноутбука в демо отсутствуют.

1. Введите код. Выберите один из трёх учебных диалогов либо загрузите свой новый JSON или текст. В начальном сеансе готовых оценок нет.
2. Нажмите «Оценить диалог». Дождитесь реального API-ответа. При отказе показывается ошибка; успешный ответ не подставляется.
3. Откройте критерий и перейдите к исходной реплике. ID, дословный текст и роль проверяются кодом. Итог с N/A рассчитывается Decimal, грубая ошибка остаётся отдельным флагом.
4. Сравните обычный пример и версию без имени либо измените значимую реплику сами. При несущественном перефразировании целевое правило должно сохраняться.
5. Проверьте карту влияния, апелляцию или независимый повтор. Сохраните JSON/CSV. Исходная оценка остаётся в истории.
6. Сохраните свою версию рубрики и выполните новую оценку. Подробный аудит поддерживает изменённые правила; официальный `results.json` требует исходную рубрику.



Демо ограничено одним общим параллельным AI-пакетом, десятью диалогами в пакете и загрузкой до 2 МБ. Действуют бесплатные квоты провайдеров. Ключи посетителю не выдаются. Данные сеанса теряются при сне или перезапуске Render: скачайте результат заранее.

Для контрольного набора используйте [локальные команды с новыми ключами](../docs/deployment/README.md) и [правила сдачи](../docs/submission.md). На обработку десяти чатов и push отведён один час до стоп-кода. Новый ключ того же проекта обычно не увеличивает общую квоту аккаунта/проекта.
