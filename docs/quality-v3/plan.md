# Качество CQA · третий цикл

Цель пользователя: максимально повысить правильность оценивания по реальной рубрике и создать полезное проверяемое отличие, не обещая победу. Дополнение: разработать и прогнать 30+ своих примеров. Бюджет 0USD; публикация и сдача не разрешены. Часовой пояс пользователя Asia/Qyzylorda.

До изменений сохранён baseline333173f0… в .local/quality-v3/baseline; исходный DEV также сохранён. Созданы 40 новых случаев:20 development +20 holdout по целым семействам. Ожидаемые признаки не попадают в запрос к модели. Holdout predictions нельзя открывать до candidate-freeze. Все отказы и попытки хранятся, нет отбора повторов по баллу.

## Реализуемые механизмы

1. Компиляция текущей рубрики в JSON-схему: отдельная шкала для каждого ID, ровно заданные ключи, источник до решения. consultation не может заимствовать 7 из dialogue; дубли JSON отвергаются до разбора.
2. Методические подсказки только для неизменённого официального критерия. Если пользователь заменил правило, шкалу или N/A, прежняя подсказка не применяется. Уточняется приоритет конкретных условий 4/7 и 0/5/15/20, а не подставляются баллы по ключевым словам.
3. Карта влияния пересмотра: для каждой альтернативы одного ответа код точно пересчитывает итог с N/A. Критические нарушения выделяются независимо от веса. Это анализ влияния, не вероятность ошибки.
4. Повторная AI-проверка без передачи первого ответа, по исходной версии рубрики. Обе оценки и расхождения сохраняются, баллы не усредняются автоматически. Согласие двух моделей не объявляется Ground Truth.
5. Дополнительный Gemini Free Tier: отдельный ключ и отдельное подтверждение тарифа, секреты отсутствуют в public-config, фиксированные адреса, без платного переключения. На Google сначала используются только наши синтетические сценарии.

## Приёмка

Старые контракты и новые отрицательные тесты должны пройти; исходный DEV не изменяется без отдельного проверенного пересчёта. Нужны реальные 40 случаев, сохранённые исходы, разбор несовпадений и отдельные числа для отказов/пропусков. Сравнивать версии на одинаковых случаях и одном провайдере, где позволяет квота; разницу моделей/промптов указывать, не называть чистой абляцией. Нужны свежий браузерный путь карты пересмотра и повторного AI, экспорт, узкая ширина и точное совпадение source hash запущенного процесса с файлами.

## Источники решений

[Groq Structured Outputs](https://console.groq.com/docs/structured-outputs), sections Schema Requirements / reusable subschemas: strict JSON поддерживает$defs/$ref, но смысл должен проверяться отдельно. [Groq Rate Limits](https://console.groq.com/docs/rate-limits): квоты организации, не ключа. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing):3.8/3.7 Flash Standard имеют Free Tier; бесплатные данные могут использоваться для улучшения продуктов. [Gemini REST discovery](https://generativelanguage.googleapis.com/$discovery/rest?version=v1beta): точные поля responseFormat/text/schema, enum APPLICATION_JSON, уровни thinkingConfig. Доступность конкретной модели и проекта подтверждается только реальным вызовом. Проверено 08.11.2026.

Калибровка по людям остаётся невозможной без независимых меток.40 авторских случаев не превращаются в человеческий GT. Результат этого цикла нельзя объявлять 100% конкурсной точностью или рыночной уникальностью.
