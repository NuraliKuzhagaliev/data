## Как работает демо

Код доступа передаётся жюри отдельно, регистрация не требуется. Каждый вход создаёт независимое рабочее пространство, SQLite и CSRF-токен. Cookie имеет Secure, HttpOnly и SameSite=Lax; выход отзывает сеанс. Проверяются Host и Origin. Серверные ключи не возвращаются браузеру и не заменяются посетителем. Доступен выбор проверенных Gemini/Groq моделей. В начальном сеансе три собственных синтетических входа без готовых оценок.

Ограничения приложения: до 16 сеансов, один общий параллельный AI-пакет, до 10 диалогов в пакете, загрузка до 2 МБ, 20 запланированных AI-диалогов в сутки текущего процесса. Внешние бесплатные квоты действуют дополнительно. При ошибке показывается отказ, подстановки успешного ответа и платного fallback нет.

На [Render Free](https://render.com/docs/free) сервис засыпает после 15 минут без трафика. Пробуждение обычно занимает около минуты. Данные файловой системы, включая сеансы, теряются при сне, перезапуске и деплое. Скачайте результат до выхода. Общие бесплатные месячные лимиты рабочего пространства также ограничивают доступность. Платные диск, БД и тарифы не подключались; keepalive не создавался. Это демонстрационная среда. Приватный DEV, аудиоссылки и база ноутбука на неё не загружены.

## Воспроизведение размещения

Один Python web service. Build: `python -m compileall -q cqa`. Start: `python -u -m cqa host`. Порт читается из `PORT`, bind — `0.0.0.0`; HTTPS origin берётся из `RENDER_EXTERNAL_URL`. Auto-deploy выключен, чтобы публикация результатов в Git не прерывала демо. Изменения кода размещаются вручную после CI.

Переменные задаются в Render: `CQA_DEMO_ACCESS_HASH` — SHA256 случайного кода доступа; `CQA_PROVIDER=gemini`, `CQA_MODEL=gemini-3.5-flash`, `CQA_TEAM_NAME=THE BOYS`, `CQA_DEMO_DAILY_LIMIT=20`, новые `GEMINI_API_KEY` и `GROQ_API_KEY`, подтверждения `CQA_GEMINI_FREE_TIER_CONFIRMED=true` и `CQA_GROQ_FREE_PLAN_CONFIRMED=true` только для фактически бесплатных аккаунтов без платного биллинга. Ключи и сам код доступа не публикуются. `.env.example` относится к локальной версии; параметры хостинга задаются в окружении сервиса.

После конфигурации дождитесь live, проверьте `/api/health` и совпадение `code_hash`, затем новый AI-вызов, цитаты и экспорт. Ключи и тела HTTP-запросов не логируются. Источники и контрольные события: `evidence/deployment/`. В браузере подтверждён рабочий сеанс при наблюдаемой ширине 455 px и вход при 375 px. Переопределение ширины рабочего сеанса на 375/1440 не применилось в среде автоматизации, поэтому эти точные размеры не отмечены как новый PASS; предыдущие локальные проверки сохранены в night-v4.

## Контрольный час с новыми ключами

Официальный PROD обрабатывайте локально, чтобы сохранить план и результаты независимо от сна Render. Новые ключи находятся в исключённом из Git файле `.local/deployment/new-keys/provider.json`. Основное подключение ноутбука не менялось.

```powershell
python -m cqa batch --config .local/deployment/new-keys/provider.json --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json
python -m cqa batch --config .local/deployment/new-keys/provider.json --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json --resume
python -m cqa build-submission --predictions .local/prod-predictions.json --dataset .local/prod.json --group prod --team 'THE BOYS'
python -m cqa check-submission --file results/prod/results.json --dataset .local/prod.json --group prod
```

Затем обычные commit и push до стоп-кода, см. [правила сдачи](../submission.md). Час включает загрузку в Git. Новый ключ того же проекта обычно не расширяет общую квоту. Реальный PROD ещё не выдан, его файл не создан из учебных данных. Человеческая экспертная точность неизвестна. Текст заявки и руководство для жюри: `submission/`. Приватный локальный пакет `.local/submission-pack/` содержит код входа, DEV, примеры, инструкции и архив исходников без API-ключей.
