## Как работает демо

По запросу команды включён `CQA_DEMO_PUBLIC_ACCESS=true`: главная страница сразу открывает приложение без кода и регистрации. Первый визит создаёт независимое рабочее пространство, SQLite и CSRF-токен; повторные визиты продолжают текущий сеанс. В режиме по умолчанию (`false`) по-прежнему требуется код доступа. Cookie имеет Secure, HttpOnly и SameSite=Lax; выход отзывает сеанс. Проверяются Host и Origin. Серверные ключи не возвращаются браузеру и не заменяются посетителем. Ввод собственных ключей в онлайн-демо отключён; такая настройка доступна локально. Доступен выбор проверенных Gemini/Groq моделей. В начальном сеансе три собственных синтетических входа без готовых оценок.

Ограничения приложения: до 16 сеансов, один общий параллельный AI-пакет, до 10 диалогов в пакете, загрузка до 2 МБ, 200 запланированных AI-диалогов в сутки текущего процесса. Внешние бесплатные квоты действуют дополнительно. При ошибке показывается отказ, подстановки успешного ответа и платного fallback нет.

## Воспроизведение размещения

Один Python web service. Build: `python -m compileall -q cqa`. Start: `python -u -m cqa host`. Порт читается из `PORT`, bind — `0.0.0.0`; HTTPS origin берётся из `RENDER_EXTERNAL_URL`. Auto-deploy выключен, чтобы публикация результатов в Git не прерывала демо. Изменения кода размещаются вручную после CI.

Переменные задаются в Render: `CQA_DEMO_PUBLIC_ACCESS=true` — открытый вход для жюри; `CQA_DEMO_ACCESS_HASH` — необязательный в этом режиме verifier для возврата к входу по коду; `CQA_PROVIDER=gemini`, `CQA_MODEL=gemini-3.5-flash`, `CQA_TEAM_NAME=THE BOYS`, `CQA_DEMO_DAILY_LIMIT=200`, новые `GEMINI_API_KEY` и `GROQ_API_KEY`, подтверждения `CQA_GEMINI_FREE_TIER_CONFIRMED=true` и `CQA_GROQ_FREE_PLAN_CONFIRMED=true` только для фактически бесплатных аккаунтов без платного биллинга. Ключи и сам код доступа не публикуются. `.env.example` относится к локальной версии; параметры хостинга задаются в окружении сервиса.

После конфигурации дождитесь live, проверьте `/api/health` и совпадение `code_hash`, затем новый AI-вызов, цитаты и экспорт. Ключи и тела HTTP-запросов не логируются. Источники и контрольные события: `evidence/deployment/`. В браузере подтверждён рабочий сеанс при наблюдаемой ширине 455 px и вход при 375 px. Переопределение ширины рабочего сеанса на 375/1440 не применилось в среде автоматизации, поэтому эти точные размеры не отмечены как новый PASS; предыдущие локальные проверки сохранены в night-v4.

## Контрольный час с новыми ключами

Официальный PROD обрабатывайте локально, чтобы сохранить план и результаты независимо от сна Render. Новые ключи находятся в исключённом из Git файле `.local/deployment/new-keys/provider.json`. Основное подключение ноутбука не менялось.

```powershell
python -m cqa batch --config .local/deployment/new-keys/provider.json --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json
python -m cqa batch --config .local/deployment/new-keys/provider.json --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json --resume
python -m cqa build-submission --predictions .local/prod-predictions.json --dataset .local/prod.json --group prod --team 'THE BOYS'
python -m cqa check-submission --file results/prod/results.json --dataset .local/prod.json --group prod
```

Затем обычные commit и push до стоп-кода, см. [правила сдачи](../submission.md). Час включает загрузку в Git. Новый ключ того же проекта обычно не расширяет общую квоту. PROD FBroker уже обработан и опубликован: 10 ok / 0 error, от получения до подтверждённого push 296,25 секунды. После него Gemini и Groq успешно проверены через Render. SWAP: 3 входа сохранены отдельно без оценки. [Текущая сводка](../../evidence/deployment/prod-submission.json). Человеческая экспертная точность неизвестна. Текст заявки и руководство для жюри: `submission/`. Приватный локальный пакет `.local/submission-pack/` содержит код входа, DEV, примеры, инструкции и архив исходников без API-ключей.

Режим открытого входа проверен 174 локальными тестами без вызовов AI. При развёртывании временные сеансы сбросятся. Возврат к коду: установить `CQA_DEMO_PUBLIC_ACCESS=false` при сохранённом корректном `CQA_DEMO_ACCESS_HASH` и выполнить deploy.

[Проверка опубликованного входа без кода](../../evidence/deployment/public-access-live.json): чистый браузер сразу открыл приложение; проверены HTTPS, ключи только на сервере, отдельные данные двух посетителей, CSRF и Origin. AI-вызовов в этой проверке: 0. [CI исходников](https://github.com/NuraliKuzhagaliev/data/actions/runs/42455862871) прошёл успешно.
