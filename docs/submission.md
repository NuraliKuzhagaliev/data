## Обработка

В UI загрузить выданный JSON, выбрать именно контрольную группу, официальную рубрику и «Оценить набор». При лимите или прерывании план и успешные оценки сохраняются; «Продолжить незавершённые» обрабатывает оставшиеся. После окончания «Выгрузить results.json» → PROD. Экспорт требует точного набора10ID. Ошибки сохраняются явно; их нельзя удалять ради метрики.

CLI для выбранного API:

```powershell
python -m cqa batch --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json
# Только если источники, код, рубрика и параметры те же:
python -m cqa batch --dataset .local/prod.json --provider gemini --model gemini-3.5-flash --output .local/prod-predictions.json --resume
python -m cqa build-submission --predictions .local/prod-predictions.json --dataset .local/prod.json --group prod --team 'THE BOYS'
python -m cqa check-submission --file results/prod/results.json --dataset .local/prod.json --group prod
```

Сохранены полный план, отдельный журнал попыток и резервная копия прежнего output. Успешные CLI-результаты не пересчитываются при совпадающей сигнатуре; изменение версии кода/модели требует нового output. Смена провайдера для незавершённых элементов доступна в UI. Код возврата2 означает отсутствие полного успешного набора; для check-submission — присутствие честных error-записей. Проверьте причину, квоту и оставшееся время.

Формат1.0: `schema_version`, `team_name`, `model:{mode,name}`, `results`. На успехе восемь `criterion_id`, boolean/число/null, rationale, номера исходных реплик с1 и итог. На ошибке `status:error`, `criteria:[]`, `score:null`, `error`. Синтетический источник, MOCK, произвольная рубрика, повтор/пропускID или неверное число диалогов отвергаются. Подробный JSON содержит больше provenance и предназначен для локального аудита, не для публикации персональных входов.
